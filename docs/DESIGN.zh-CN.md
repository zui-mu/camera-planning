# 家具中心、姿态无关的多相机布局设计

> 版本说明：本页保留 0.3 表面＋构图包络基线设计。0.4 主方法改为自由空间观测域、方向性下尾部目标与自适应候选；实现和运行以 [ROBUST_PLANNING.zh-CN.md](ROBUST_PLANNING.zh-CN.md) 为准。旧包络包含声明的人体高度，不能称为严格零人体尺度。

## 1. 项目情景和研究对象

YSynthetic 希望从室内三维场景出发，生成与家具交互的人体内容，再恢复可复用的三维人体。这里要补的是生成前的相机布局模块。

当前目标链路应准确写成：

```text
已知场景 S + 目标家具 F + 相机预算 B + 固定成像规格 K
    ↓ 本项目：静态相机集合规划
带 camera_id 的 K / R / T
    ↓ 空场景渲染
空场景图像；可选的运镜序列是后续另一个模块
    ↓ 外部图像/视频生成
带人物内容
    ↓ 目标视角匹配、挑选可用帧
与原相机相对应的人物图片
    ↓ SAM 3D Body 逐图估计
每个视角的 MHR 人体提案
    ↓ scene_consistency → pose_consensus → body_fuse
统一世界坐标中的融合人体
```

**SAM 3D Body 是单图人体估计模型；多视角一致性和融合是当前项目自己的模块组合。** 不把 MAMMA 当作本方向的目标后端，也不把库里仍然存在的旧入口误认为当前采用的主链路。

上游以后可能使用 LLM 为家具生成交互提示词；相机规划的基本 formulation 不依赖这条提示词，也不要求它预测未来具体姿态。将来若添加交互先验，应作为独立、明确标识的实验分支，不能悄悄改变主问题的信息条件。

## 2. 目标是什么，不是什么

最终研究目标仍是选择集合 C，满足 |C|=B，使未知未来人体 H 的下游恢复损失尽量低：

`C* = argmin E[ L( Reconstruct(Images(S,H,C)), H ) | S,F ]`。

这里的 H 在正式规划时不可见，生成过程还有随机性，因此不能把 H 的概率位置伪装成已知输入。当前可计算问题改为：覆盖目标家具可拍摄表面，同时保证由家具几何和声明的完整人物尺寸导出的构图包络处在安全画幅内，并让视角具有有效基线。RQ1/RQ2 再判断这个确定性代理是否与真实后端的回环偏差相关。

不是以下问题：

- 不是预测人物最可能出现的位置；主方法没有站/坐/躺的概率图。
- 也不是单纯为家具做三维扫描；构图包络和距离下限服务于未来完整人体入镜。
- 不是先看见一个真人，再主动追着他选择下一帧；当前是一开始就选好的静态集合。
- 不是用 H_ref 的精确关节位置来优化相机，然后宣称不知道人体。
- 不是一次解决运镜、视频生成一致性、人体重建、动作拼接全部问题。

初始交付是“一组相机”，不是“已保证可飞行的相机轨迹”。接口中保留 `trajectory_status: not_planned`，避免下游把数组顺序当作连续无碰撞运镜。

## 3. 阶段 A：输入规范化

输入 `PlanningRequest` 包含 scene_id、目标家具边界、允许放相机的范围、up_axis、地面高度、米制坐标、相机预算、固定 K 与 geometry backend。旧基线可使用障碍物 AABB；真实 Blender 入口会同时写出 evaluated 世界三角网格和哈希。

初版要求上游提供已经变换到同一个世界坐标的几何。目标家具由 object_id 选择；其名称并不能代替网格、尺度和位姿。摄像机姿态按 OpenCV world-to-camera 存储。

为什么先显式输入而不是声称自动读取 USD：真实资产可能经过 Houdini/Blender 层级变换、缩放、upAxis 转换。直接读取包围盒而不应用世界变换，会让规划和渲染处于不同坐标系。首先把契约锁定，后续用适配器完成自动提取。

当前默认的 `aabb_boxes` 路线由 `blender_extract_scene_boxes.py` 自动读取 evaluated 对象的世界坐标包围盒，目标家具和非结构物成为轻量盒体；规划完成后仍回到原始高模场景渲染。名称含 floor/wall/ceiling 等 token 的房间壳默认不转成实心盒，否则一个环绕全屋的 wall AABB 会错误占满室内。这个名称过滤必须查看 manifest 人工核验。

可选的 `triangle_mesh_proxy` 路线由 `blender_export_scene_geometry.py` 输出 evaluated 世界三角网格、面到 object_id 的归属和 BVH 遮挡；它保留为更精细的对照，可对目标降面、对非目标超大网格使用 AABB 代理。两条路线都不修改原始渲染资产。

## 4. 阶段 B：建立确定性的观察域

观察域由两部分组成。第一部分从目标家具的真实三角表面按面积采样，并去掉明显朝下、实际不需要拍摄的底面。第二部分是构图包络：将家具边界在水平面扩展固定 clearance，竖直范围从地面上方安全量延伸到 `max(声明的完整人物高度, 家具顶部+top_clearance)`，再删掉静态实心物内部点。

这个包络不是“人会在这里”的概率预测；每个点只表示相机应当保留的确定性画面余量。因此倒坐、趴卧或爬到家具上不会因为不符合某个姿态先验而在规划阶段被排除。它也不保证任何具体动作都无遮挡，具体人体自遮挡仍由下游实验测量。

家具表面和构图包络分别分成水平四象限×高低两层。AABB 模式中的“家具表面”指包围盒六个面，不等于真实曲面；三角网格模式才按实际三角面面积采样。两类点使用不同 zone 编号，评分按非空 zone 等权平均，避免表面积较大的一面或包络体积较大的部分压倒其他方向；同时保留最差 zone 项。

`full_body_height_m`、水平 clearance 和图像边缘比例都是可声明、可消融的工程约束，不是学习式人体先验。候选注视点来自家具中心＋通用高度，不能看着 H_ref 的骨盆自动对焦。

## 5. 阶段 C：生成相机候选

先从目标网格水平投影做 PCA，建立家具局部 OBB，再采用“局部 OBB 扩展边界＋多高度＋多注视高度”。对于局部水平单位方向 d、家具半尺寸 h 和扩展量 δ，取：

`t = min_a (h_a + δ) / |d_a|`，`camera_horizontal = furniture_center + t d`。

也就是说射线与家具自身朝向下的扩展矩形相交，得到相机位置；这与按固定半径画圆不同。枚举多个 δ、高度和方位角。

先做硬过滤：相机及 clearance 需在允许范围内；不能处在障碍物或其膨胀区域；相机到目标 OBB 的距离必须位于声明上下限。之后分别检查家具表面与构图包络的最低可见比例，任一不达标就剔除。

`camera_clearance_m` 针对相机放置，不是人物路径规划中的身体半径。两者不能混淆。

每个候选始终保存稳定 camera_id。候选不足 B 时应报错，而不是重复相机来凑数量。过滤是所有基线共享的，不给所提方法额外优待。

## 6. 阶段 D：计算单视角几何证据

对每个相机 c 和观察域点 x：

1. 将 x 变换为相机坐标，必须在相机前方。
2. 用 K 投影，像素必须在扣除 `image_margin_ratio` 后的安全画幅内。
3. 从相机中心向 x 发射线段，检查静态家具/墙体遮挡。
4. 保存可见性 V(c,x)、投影雅可比、像素密度近似和观察方向。

旧基线射线使用 solid AABB slab intersection，对椅子腿之间、薄椅背和挖空家具过于保守。当前真实场景入口使用三角网格 BVH：遮挡按 open segment 与实际三角形相交判断，闭合 target/家具用射线奇偶判断内部，camera clearance 用点到三角形距离。人体自身手臂挡身体、背面看不见正面纹理等仍没有建模；复杂大网格的最近表面查询也还没有专用空间加速。

像素密度项用 `fx*fy/z²` 做正对小面片的面积密度代理，归一化后截断在 1。没有面法线就不能称为精确 Pixel-per-Area；也不能将它称为人体分辨率质量的测量结果。

## 7. 阶段 E：相机集合评分

`Q(C) = wc*coverage + wm*multiview + wi*information + wr*resolution + wz*worst_zone`。

五项现在的确切含义：

| 分项 | 初版计算 | 注意事项 |
| --- | --- | --- |
| coverage | 家具表面/构图包络每个 zone 内至少被一台相机看到的点比例，再 zone 等权平均 | 同时另报两类点各自覆盖率 |
| multiview | 采样点存在两台可见相机，且观察射线夹角不接近 0° 或 180° | 使用点处射线，不能只看相机朝向差 |
| information | 累加投影 JᵀJ/σ²，加先验后算 logdet，再做有界变换 | 三维点测量的几何信息量，不是 SAM3D 参数 Fisher |
| resolution | 每个点取选中相机中最好的归一化密度，再区域均衡 | 可饱和，避免只奖励无限接近 |
| worst_zone | 最弱非空区域的有效双视角覆盖比例 | 是风险启发式，不是实际最差人体损失 |

双视角默认要求 `15° <= θ <= 165°`。阈值是待消融超参数，不是论文已经证明对 MHR 最优。特别注意 θ=180° 的两条共线射线也会退化；所以代码用 `abs(cos θ)`，不是“相隔越远必然越好”。

信息项的原始形式是：

`I_x(C) = Σ_c V(c,x) J(c,x)ᵀ J(c,x) / σ_pixel²`；
`g_x = log det(I_3 + s_info² I_x(C))`；
`information_x = 1 - exp(-g_x/12)`。

这里假设理想点对应、独立同方差像素噪声和局部线性化。这些并不是 SAM 3D Body 的真实误差模型。本地 body_fuse 并非直接执行这套三角化，因此信息项必须通过 RQ2 验证；若与下游效果无关，就降低权重或替换，不能为了理论好看一直保留。

目前权重只是启动实验的默认值，不经过测试集调参。未来可按验证集优化、学习排序，或用约束方式代替加权和，但应保留可解释分项和无学习基线。

## 8. 阶段 F：选 B 台相机

初版从空集合开始，每轮加入提升 Q 最大的候选；选满后做有限轮单相机替换：用未选候选替换一个已选相机，只接受严格增益。

选择的是集合增益，不能把每台相机独立评分后取前 B，否则可能选到 B 个几乎重合的视角。

目前同一可行候选池上的基线有：随机无放回、均匀方位角就近选择、方向最分散、单覆盖贪心。小候选池可穷举，帮助量化优化器本身的局部最优缺口。

组合目标含双视角互补和最弱区域项，**没有证明次模性，也不宣称 1−1/e 保证**。未来若要引用严格保证，应另开满足理论假设的纯 logdet/覆盖子问题。

大规模时先缓存 `N_camera × N_point` 的证据；当前实现会重新计算集合分数，适合小研究原型，不是已经工程优化的大场景实时系统。可以逐步加增量信息矩阵、候选粗细分层、几何加速，先不要直接引入昂贵 RL。

## 9. 阶段 G：导出与生产入口

主要输出 `cameras.json` 必须严格兼容 YSynthetic；分数、米制、upAxis、几何来源和算法日志放到旁边的 `camera_plan_result.json`。这避免往现有禁止 extra 字段的 schema 塞自定义研究信息。

正式入口 `plan()` 的输入结构不包含 H_ref、生成后的人物图、真实关节或后端误差。实验入口 `prepare_rq1()` 才接触 reference，仅用于固定实验身份和之后的渲染/评估。哈希防止计划和已缓存证据错配，但不能代替对数据来源的人工审计。

以后并入 YSynthetic 时可以增加一个薄的 `camera_planning` workflow，调用这里的核心库并导出 artifact。无需修改逐视角模型本身，也不要将 ray casting、Blender 和 CUDA 网络耦合在同一个文件。

## 10. 阶段 H：用当前后端校准，而不是用文献替代验证

RQ1：同一个冻结参考人体、同一场景、同样 B，仅改变相机集合，重新渲染并经同一后端融合，误差是否改变？

RQ2：几何代理分数能否排序这些集合？加入哪些特征能改进跨家具、跨人物泛化？

RQ3：将布局放回生成视频主链，匹配成功率、有效视角数、人体一致性和融合成功率是否仍改善？

论文机会更可能来自“姿态无关的家具中心鲁棒构图＋遮挡感知集合优化＋下游人体后端校准＋可验证管线”的组合，而不是相机位置有影响这个已被研究多年的结论。若 RQ1 效应很小，应先排查候选域、渲染域差异、检测失败和后端是否退化为单视角主导；不应直接宣布方向成立或失败。
